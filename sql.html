SQL

The query language behind almost every application's database. This track covers reading, filtering, joining, and aggregating data.

On this page

  1. 1. SELECT & filtering
  2. 2. Sorting & limiting

1. SELECT & filtering

SELECT name, skill_level
FROM learners
WHERE skill_level = 'beginner';

SELECT chooses columns, FROM chooses the table, and WHERE filters rows. Combine conditions with AND / OR.

Try it: paste this into the playground's SQL mode to see sample output.

2. Sorting & limiting

SELECT name, joined_at
FROM learners
ORDER BY joined_at DESC
LIMIT 5;

ORDER BY ... DESC gets the newest rows first; LIMIT caps how many rows come back — useful for "top 5" style queries.

3. Joins

SELECT learners.name, courses.title
FROM learners
INNER JOIN enrollments ON learners.id = enrollments.learner_id
INNER JOIN courses ON enrollments.course_id = courses.id;

INNER JOIN returns only rows that match in both tables. LEFT JOIN keeps every row from the left table even without a match, filling unmatched columns with NULL.

4. Aggregation & GROUP BY

SELECT skill_level, COUNT(*) AS total
FROM learners
GROUP BY skill_level
ORDER BY total DESC;

COUNT, SUM, AVG, MIN, and MAX summarize groups of rows. GROUP BY defines what counts as a "group."

5. Basic database design

CREATE TABLE learners (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  skill_level TEXT DEFAULT 'beginner'
);

CREATE TABLE courses (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL
);

CREATE TABLE enrollments (
  learner_id INTEGER REFERENCES learners(id),
  course_id INTEGER REFERENCES courses(id)
);

Splitting data into separate tables linked by IDs (foreign keys) avoids duplicating information — this is the core idea behind relational database design.
